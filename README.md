# ⚡ VoltYo‘l — «Где зарядить»

Telegram-бот для поиска зарядок электромобиля по геопозиции или названию города. Показывает одну карту и до двух ближайших станций, объясняет пробелы в данных и собирает сообщения водителей об ошибках.

Работающий экземпляр: [@VoltYolBot](https://t.me/VoltYolBot). Языки: русский, узбекский и английский.

## Для кого продукт и какую проблему решает

Основная аудитория — водители электромобилей в Узбекистане и соседних странах, которым нужно быстро выбрать зарядку рядом или заранее посмотреть другой город. Покрытие зависит от OpenStreetMap: наличие точки не подтверждает, что зарядка сейчас работает, свободна и подходит машине.

Продукт помогает принять следующий шаг: увидеть расположение станций, сравнить расстояние и доступные разъёмы, открыть маршрут. В отличие от таблицы источника, бот принимает геопозицию, упорядочивает результаты, показывает их на карте и связывает обратную связь с конкретной станцией по OSM ID.

Если адрес, название или сведения о разъёмах отсутствуют, это отмечается в карточке. Сохранённые устаревшие данные и частичная выдача резервного поиска также имеют отдельные предупреждения. Сообщения водителей сохраняются в PostgreSQL для последующей проверки; автоматической проверки и публикации исправлений пока нет.

## Почему такая форма

Telegram был задан как формат продукта. Он подходит сценарию короткого запроса: отправить геопозицию, получить результат и открыть маршрут, без отдельной регистрации и установки нового приложения.

Ответ состоит из одной карты и двух коротких рекомендаций. Карта даёт обзор района, а две карточки помогают выбрать следующий шаг без длинной ленты из десятков сообщений. Номера 1 и 2 на карте совпадают с рекомендациями; синяя точка обозначает место поиска. При одной найденной станции приходит одна рекомендация, при пустой выдаче — сообщение об отсутствии результатов.

Кнопки клавиатуры делают основные действия видимыми: геопозиция, город, язык, сообщение об ошибке и помощь. Команды остаются дополнительным способом управления.

## Как запустить

### Что потребуется

- Python 3.11 или новее.
- Docker с Docker Compose для локальных PostgreSQL и Redis **или** доступ к уже запущенным серверам этих сервисов.
- Токен Telegram-бота, полученный у [@BotFather](https://t.me/BotFather).
- Доступ к интернету: Telegram API и публичные сервисы OpenStreetMap используются во время работы.

Все команды ниже выполняются из корня проекта.

### 1. Настроить окружение

При первом запуске создайте файл настроек:

```sh
cp .env.example .env
```

Если `.env` уже существует и содержит ваш токен, отредактируйте его вместо повторного копирования шаблона. Основные параметры:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен_из_BotFather
TELEGRAM_MODE=polling
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/evchargers
REDIS_URL=redis://localhost:6379/0
```

Токен хранится в `.env`, который исключён из Git. Остальные параметры и адреса источников перечислены в `.env.example`.

### 2. Запустить PostgreSQL и Redis

Для локального окружения из проекта:

```sh
docker compose up -d --wait
```

Compose создаёт базу `evchargers`, сохраняет данные в Docker volumes и публикует PostgreSQL на порту 5432, Redis — на 6379. Значения подключения выше подходят этому локальному окружению.

Для существующего PostgreSQL укажите его строку подключения в `DATABASE_URL` и заранее создайте нужную базу. pgAdmin — приложение для управления PostgreSQL; backend подключается к самому серверу базы. При старте приложение создаёт таблицы и добавляет недостающие поля, поэтому пользователю базы нужны соответствующие права. Если PostgreSQL уже занимает порт 5432, второй контейнер базы не нужен; при необходимости отдельно поднимите только Redis:

```sh
docker compose up -d redis
```

### 3. Установить зависимости и запустить приложение

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В режиме `polling` FastAPI сам запускает получение обновлений Telegram. Публичный HTTPS-адрес для локальной проверки не нужен. Терминал с приложением должен оставаться открытым.

Запускайте **один экземпляр** приложения для одного токена. Если на этой машине уже работает служба `voltyol-bot`, перед ручным запуском остановите её:

```sh
systemctl --user stop voltyol-bot
```

В существующем пользовательском сеансе службой можно управлять командами:

```sh
systemctl --user status voltyol-bot
systemctl --user restart voltyol-bot
```

Эта служба создавалась для текущего сеанса и не настроена на автоматический запуск после перезагрузки. Если её нет, используйте ручной запуск выше. Логи службы находятся в `work/bot.log`.

### 4. Проверить, что API запустился

```sh
curl http://127.0.0.1:8000/health
```

Ожидаемый ответ в локальном режиме:

```json
{"status":"ok","telegram_mode":"polling"}
```

Дополнительно можно открыть [документацию API](http://127.0.0.1:8000/docs). Успешный `/health` подтверждает запуск приложения, но не доступность внешних источников и не доставку сообщений в Telegram.

## Что нажать, чтобы проверить бота

Если используется свой токен, откройте своего бота. Для существующего экземпляра — [@VoltYolBot](https://t.me/VoltYolBot).

| Шаг | Действие | Что должно произойти |
| --- | --- | --- |
| 1 | Нажать **Start** или отправить `/start` | Приветствие и основная клавиатура; прежний незавершённый ввод сброшен. |
| 2 | Нажать **❓ Помощь** или отправить `/help` | Инструкция по поиску, карте, рекомендациям и кнопкам. |
| 3 | Нажать **🌐 Язык**, выбрать English или Oʻzbekcha | Текст и клавиатура переключатся; выбор сохранится для следующих запросов. |
| 4 | Нажать кнопку отправки геопозиции и разрешить Telegram отправить местоположение | При найденных станциях: одна карта, затем до двух отдельных рекомендаций. На карте и карточках совпадают номера 1 и 2; указаны расстояния и доступные сведения. |
| 5 | Нажать **🧭 Маршрут** у рекомендации | Откроется маршрут от места поиска к выбранной станции в OpenStreetMap. Расстояние в карточке считается по прямой, а не по дороге. |
| 6 | Нажать **✅ Работает** у станции | Подтверждение сохранится, бот поблагодарит. Это отзыв пользователя, а не проверка оператора зарядки. |
| 7 | Нажать **⚠️ Проблема** у станции и описать ошибку следующим сообщением | Сообщение сохранится вместе с OSM ID выбранной станции. |
| 8 | Нажать поиск по городу и написать `Ташкент` | Поиск вокруг найденного центра города; далее тот же ответ с картой и рекомендациями. Название города также можно отправить прямо сообщением. |
| 9 | Нажать **📝 Сообщить об ошибке** и отправить текст | Сохранится общее замечание, без привязки к конкретной станции. |
| 10 | Начать жалобу, затем отправить `/start` или выбрать поиск по городу | Новый сценарий заменит старый; название города не должно сохраниться как текст жалобы. |

Для проверки на уже использовавшейся базе удобно начать с Ташкента. На чистой базе количество результатов зависит от доступности источников и покрытия OSM; фиксированное число станций не гарантируется. Для геопозиции радиус по умолчанию — 5 км (`SEARCH_RADIUS_METERS`), для города — 15 км от найденного центра.

Проверку записи обратной связи можно выполнить в pgAdmin:

```sql
SELECT osm_type, osm_id, status, message, created_at
FROM station_feedback
ORDER BY created_at DESC
LIMIT 5;

SELECT message, created_at
FROM reports
ORDER BY created_at DESC
LIMIT 5;
```

### Как трактовать пограничные случаи

- **Одна станция:** одна карта и одна рекомендация; подпись упоминает только номер 1.
- **Ничего не найдено:** отдельное сообщение без выдуманных станций.
- **Источник недоступен:** используются сохранённые данные либо резервный поиск; если данных нет, бот объясняет недоступность сервиса. Это отличается от успешного поиска с пустым результатом.
- **Данные неполные:** карточка перечисляет отсутствующие сведения. Наличие адреса и разъёма не доказывает текущую работоспособность зарядки.
- **Резервная выдача:** явно отмечено, что показана только часть зарядок района.
- **Не загрузился фон карты:** отметки станций остаются на изображении, а подпись предупреждает о проблеме с подложкой.

## Что было задано и что решено самостоятельно

Заданные требования: Telegram-бот, Python/FastAPI, PostgreSQL, кэш, три языка и кнопки клавиатуры. Формат «одна карта + две рекомендации» также выбран по запросу пользователя.

Самостоятельные решения в реализации:

| Решение | Зачем |
| --- | --- |
| Ранжирование по расстоянию по прямой | В данных нет надёжного текущего статуса, цены и совместимости с машиной; правило выбора простое и проверяемое. |
| Разделение отсутствующих, сохранённых и частичных данных | Пользователь видит ограничения выдачи до поездки. |
| Сохранение OSM ID и происхождения записи | Отзыв можно связать с конкретной точкой, а источник — отследить. |
| PostgreSQL для данных и обратной связи; Redis и файловый кэш для ускорения | Станции и отзывы переживают перезапуск, повторные запросы меньше зависят от сети. |
| Резервные источники и общий бюджет ожидания Overpass | Недоступный внешний сервер не должен каждый раз задерживать ответ на десятки секунд. |
| Точные координаты в ключе поиска и пересчёт расстояний при чтении кэша | Смена геопозиции не должна возвращать старое расстояние. |
| Переиспользование соединений Telegram, готовой карты и `file_id` фото | Уменьшает повторную отрисовку и загрузку одинаковой картинки. |
| Одно состояние незавершённого ввода на пользователя | Поиск, помощь и жалоба не перехватывают сообщения друг друга. |

Это инженерные и продуктовые предположения прототипа, а не выводы из проведённого исследования пользователей.

## Что отрезано от первой версии

- Онлайн-статус зарядки, занятость разъёмов, актуальные тарифы, бронирование и оплата: для этого нужны интеграции с операторами, а не только OSM.
- Профиль автомобиля и автоматическая проверка совместимости разъёма. Сейчас доступны только сведения из источника.
- Планирование дальней поездки с запасом хода, временем зарядки и расчётом маршрута внутри бота. Маршрут открывается во внешнем сервисе.
- Автоматическое редактирование OpenStreetMap по жалобе пользователя. Отзывы сохраняются; подтверждение изменения источника требует отдельного процесса.
- Интерфейс модератора, проверка достоверности отзывов и сводный рейтинг работоспособности. Кнопка «Работает» записывает отзыв, но он пока не меняет порядок рекомендаций.
- Собственное мобильное приложение, интерактивная карта внутри Telegram, уведомления и избранное. Текущая карта — статичное изображение.
- Полная загрузка всех зарядок страны и гарантия покрытия каждого района. Резервный поиск возвращает выбранные совпадения.
- Продакшен-развёртывание с постоянным автозапуском, несколькими экземплярами, административной авторизацией и защитой публичного API. Текущий запуск рассчитан на локальный прототип.

## Как устроены данные и кэш

Стек: Python, FastAPI, asyncpg/PostgreSQL, Redis, httpx и Pillow. PostgreSQL хранит пользователей, станции, общие сообщения и отзывы о конкретных станциях. Таблицы создаются при старте.

`OVERPASS_URL` в шаблоне использует публичный глобальный сервер VK Maps; при сбое пробуется `OVERPASS_FALLBACK_URL`. Полный запрос использует `out body center`, чтобы получить координаты узлов и центры площадных объектов. Список публичных серверов есть в [OSM Wiki](https://wiki.openstreetmap.org/wiki/Overpass_API).

Сначала проверяются кэш и сохранённые свежие станции. При отказе Overpass доступны старые записи с предупреждением; если их нет, разрешён один ограниченный поиск Nominatim. Он возвращает до 10 совпадений в небольшой области, без пагинации и обхода сетки. Выдача помечается как частичная. Источник и этот признак сохраняются в базе.

Оба вида запросов Nominatim — город и резервный поиск станций — используют общий ограничитель не более одного запроса в секунду и часовой кэш Redis. Соблюдайте [правила публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/); это не сервис для массовой выгрузки всех POI. Для роста нагрузки потребуется другой или собственный сервис, настраиваемый через `NOMINATIM_URL`. Резервный поиск отключается параметром `NOMINATIM_FALLBACK_ENABLED=false`. Ограничения выдачи описаны в [документации поиска](https://nominatim.org/release-docs/latest/api/Search/).

Снимок станции считается свежим в течение шести часов. Кэш поиска Redis по умолчанию живёт 15 минут. Общий лимит ожидания Overpass — 4 секунды (`OVERPASS_BUDGET_SECONDS`); после сбоя он пропускается на 60 секунд (`OVERPASS_COOLDOWN_SECONDS`). Время резервного поиска и отправки сообщений считается отдельно.

Подложка карты загружается по `MAP_TILE_URL` только для текущей области и кэшируется минимум семь дней в `MAP_TILE_CACHE_DIR`, с атрибуцией и идентифицирующим User-Agent согласно [правилам OSM-тайлов](https://operations.osmfoundation.org/policies/tiles/). Готовая карта кэшируется на час; повторная отправка может использовать Telegram `file_id`. В Telegram впервые загружается JPEG, PNG остаётся для предпросмотра. При неполной загрузке подложки короткий кэш позволяет повторить её получение.

## Автоматическая проверка и диагностика

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют языки и помощь, смену сценариев, карту и рекомендации, разъёмы и неполный адрес, расстояния в кэше, поведение при отказе источников и оптимизации отправки. Отправка Telegram и ответы внешних источников в этих тестах имитируются. Пройденные тесты не заменяют ручной сценарий выше и не подтверждают доставку на телефон.

Отчёты последних проверок находятся в `outputs/final-bot-qa.md`, `outputs/map-response-retest.md` и `outputs/performance-report.md`. Это результаты конкретных прогонов, а не гарантия текущей доступности внешних сервисов.

`work/latency.jsonl` записывает очередь обработки, время поиска, карты, принятия запросов Telegram API и полного ответа. В журнале есть update ID и длительности; нет chat ID, координат, текста сообщений или токена. Файл ротируется при 2 МБ. `telegram_age_s` приблизителен из-за секундной точности времени Telegram; время показа сообщения на телефоне не измеряется. Таймаут long polling 25 секунд означает ожидание новых событий, а не обязательную задержку ответа.

## API и вариант с webhook

| Метод | Назначение |
| --- | --- |
| `GET /health` | Состояние запущенного приложения. |
| `GET /api/stations?lat=41.31&lon=69.28&radius=5000` | Поиск станций с координатами, расстояниями, тегами и признаками ограничений. |
| `POST /api/reports` | Общее замечание; пример тела: `{"telegram_id":123,"message":"Connector is broken"}`. |
| `POST /telegram/webhook` | Получение событий в режиме webhook; в polling возвращает 409. |

Для webhook установите `TELEGRAM_MODE=webhook`, задайте `TELEGRAM_WEBHOOK_SECRET`, опубликуйте FastAPI по HTTPS и зарегистрируйте в Telegram адрес `https://YOUR_HOST/telegram/webhook` с тем же секретом. Это альтернативный режим; для локальной проверки достаточно polling.
